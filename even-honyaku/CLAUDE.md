# even-honyaku (翻訳)

G2 app for live English ⇄ Japanese conversation. Sibling project in the `even-` workspace
(https://github.com/oggunderscore/even-development) — platform docs are in that repo's `even-realities-docs/`.

- **Always-on listening** (`start auto`, off until the wearer resumes it): Deepgram nova-3 with a dedicated `ja` and a dedicated `en` stream arbitrated in `src/core/arbiter.ts` (Japanese-biased; always dual, no setting). Japanese heard → glasses show **English**; English heard → **romaji** to read aloud.
- **Hold to talk** (`start talk`): English-only stream for the wearer (phone button); releasing returns to always-on. No mode switch anywhere.
- **Voice filter** (1.1, `voice.filter`, default on): every final is attributed to the wearer / other person / unsure *before* it is translated, so the wearer's own Japanese (usually a suggested reply read aloud) is never translated or answered. `core/echo.ts` (L0: text matches a suggested reply) + `core/voice.ts` (L1: speaking level, L2: voiceprint) fused by `verdict()`; `core/dsp.ts` extracts MFCC+pitch features; `VoiceTimeline` keeps ~45 s of PCM on the same clock Deepgram uses for each final's `start`/`end`.
- **Predictive Conversation Mode** (1.1, `mode: 'predictive'`): after the other person's turn (900 ms quiet, merged phrases, 10 s boundary — `core/turns.ts`) `core/predict.ts` asks the LLM for one reply (statement) or 2-3 different options (decision), as romaji. Needs OpenRouter/Claude; Google can't. Glasses side is `predictive.ts` (pure view model) rendered by `display.ts`.

## Layout
- `src/core/` — the isomorphic engine (Deepgram streams + arbiter, translation providers, romaji, key validation, voice filter, reply prediction, `engine.ts`); runs in the WebView; there is **no server** (the Even app hosts a WebView, so users bring their own keys and the phone calls Deepgram + the translation provider directly). No Node-only APIs, no `process.env`. Host glue: `src/romaji-browser.ts` (tests use `src/test/romaji-node.ts`).
- `src/` — Vite + TS WebView app. `main.ts` controller, `display.ts` glasses containers, `ui.ts` phone UI (terminal theme, sharp corners; Feed + Voice + Settings tabs), `settings.ts` user keys + choices, first-run `setupSteps` (bridge storage + localStorage), `settings-change.ts` (what a settings change requires: restart the stream? which key checks?), `core/models.ts` (the ranked model dropdown lists and prices), `session.ts` (runs the engine, sends `config` first), `input.ts` gesture classification, `protocol.ts` message types between the app and the engine, `menu.ts` the contextual-menu items and what picking one does, `predictive.ts` the Predictive screen, `enroll.ts` voice-profile enrollment prompts, `voice-store.ts` the on-device voiceprint.

## Constraints that shaped the design
- **First run:** until both a Deepgram key and one translation key are set, the glasses show a setup screen (`Display.setSetup`) and the phone opens Settings.
- **Input** (classified in `src/input.ts`): on the glasses a **single tap** pauses/resumes listening (delayed `SINGLE_TAP_MS` = 350 ms in `main.ts` and cancelled by a `double_click`, so a double tap never also toggles it; a tap that merely woke the app after the exit dialog's "No" doesn't toggle). A **double tap on the home page must call `shutDownPageContainer(1)`** (`src/exit.ts`; the system confirmation) — the store rejected an in-app menu on double tap and mode 0 (`0` is only for cleanup after the user has already confirmed), so never put anything else on double tap and keep that test's mode at 1. Nothing is torn down first, so answering "No" leaves everything working. The wearer's other controls are in the **OS contextual menu** (tap then long press): `menu.ts` builds the items (Pause / Resume, Mode, Replies, Options, Voice filter, Kana), `Display` declares them as `menuObject` on every page create/rebuild (omitting it clears the menu), and a pick arrives as `menuItemClickEvent.itemID` (`menuClick` in `input.ts`; id = position + 1). Items are fire-and-forget: labels that show state are updated by rebuilding the page (`Display.configure`, one rebuild for mode + labels). Labels must stay ≤ 18 characters (the glasses truncate longer ones with "…"; max 32 bytes, 10 items). A swipe scrolls the feed one entry at a time (`src/feed.ts`) or, in Predictive mode, moves the `▶` highlight (and past the first option reads earlier turns, down returns to the live turn). **Plain long press is deliberately unused**: users bind it to their own function. Hold-to-talk-in-English lives on the phone button (pointer events).
- **Layouts** (`display.ts`): `standard` (header/body/footer) and `predictive` (header + a 256 px body = 9 rows). Page rebuilds are serialized and clear the sent-text cache; everything else is `textContainerUpgrade`. Exactly one container (the body) captures input. There is no in-app menu overlay any more.
- **Kana/kanji on the glasses**: the font is reported (by the owner, on hardware) to render them, but the docs don't confirm it and widths are unknown, so romaji is always drawn and Japanese script is opt-in (`glassesKana`, Settings → "Kana on glasses"; `feed.ts` assumes 27 px per CJK glyph). Unknown glyphs are silently dropped. Romaji is plain ASCII; macrons are stripped/doubled in `core/lang.ts` (`arigatou`, not `arigatō`). `▶ ● ○` are in the font and used as markers.
- **No keys in the bundle** (`.ehpk` is extractable): users enter their own in Settings. Direct mode calls Deepgram (WebSocket, `['token', key]` subprotocol) and the translation providers (all allow browser CORS; Anthropic needs `anthropic-dangerous-direct-browser-access`) straight from the WebView.
- Mic = 16 kHz mono s16le PCM via `audioControl(true)` / `event.audioEvent.audioPcm` (may arrive as `Uint8Array`, `number[]` or base64 — see `src/pcm.ts`). No audio output on G2.
- Capture stops when the WebView is suspended (Android) → re-armed on `FOREGROUND_ENTER_EVENT`.
- `app.json` `network.whitelist` lists the provider origins (Deepgram, Google Translate, OpenRouter, Anthropic).
- The kuromoji romaji dictionary (~17 MB) ships as `public/dict/*.dat.gz.bin` (copied by `scripts/copy-dict.mjs`; the `.bin` suffix stops hosts auto-decompressing `.gz`). It's only fetched for the Google provider.

## Staying alive
- The `onEvenHubEvent` subscription is made once and **never removed** (removing it before the exit dialog broke "No → double-tap again", and on SYSTEM/ABNORMAL_EXIT it killed controls for good). `SYSTEM_EXIT` only halts capture; the next gesture re-arms it.
- Capture dies silently when the phone locks / the WebView is suspended (mic stops, Deepgram sockets drop, timers freeze). `resumeCapture()` in `main.ts` rebuilds the stream + mic on `FOREGROUND_ENTER`, `ABNORMAL_EXIT`, `visibilitychange`, and when a 5 s wall-clock tick finds a >20 s gap. It keeps the user's pause choice.
- Glasses writes are deduped and live interim text is throttled (`display.ts`) so BLE isn't flooded.

## Settings form
- There is **no Save button**: `ui.ts` commits the form (keys ~700 ms after typing stops or on blur; provider/model/preferences at once) via `onChange` → `main.ts onSettingsChange`, which saves, hands the engine the new values (`session.reconfigure()`, or `reset()` only when the Deepgram key changed) and runs the checks `planChange` asks for. A key with the wrong characters/length is never saved (the saved one stays) and shows ✗ at once.
- Key checks are scoped (`stt` = Deepgram socket; `translate` = provider key probe then a sample translation **with the chosen model**) and carry a request `id`; `main.ts` ignores an answer whose id isn't the newest for its scope. Failure text is written for users (`core/probes.ts`); results never contain a key.
- Models are dropdowns from `core/models.ts` (ranked, first = default; labels short because a phone's closed select can't wrap, prices live in the compare panel). A saved model not on the list is kept as "Custom". Re-rank by editing that file; prices there are a dated snapshot of OpenRouter's catalog.
- The guide dialog (`#guide`, opened by `? CONTROLS`) is plain HTML with focus handling in `ui.ts wireGuide`; update its text whenever a gesture changes.

## Voice profile
- Stored locally only (`voice-store.ts`: bridge storage mirrored to localStorage, key `honyaku.voice.v1`); never sent anywhere, never logged. `PRIVACY.md` covers it. Enrollment (`enroll.ts`) and the live test run entirely on the phone with the glasses mic and pause normal listening while they run (`lab` in `main.ts`).
- The engine learns from certain moments only (phone hold-to-talk, echo-confirmed replies) into `adapt` samples (max 16 per language) that never replace the enrolled `seed` samples. It emits `voice_profile` (debounced) and `main.ts` saves it.
- Tests use synthetic speakers (`src/test/synth.ts`): they prove the plumbing and that clearly different voices separate, **not** real-world accuracy. Tune thresholds with real glasses audio via the VOICE tab's live test (`analyze()` in `core/voice.ts` is the same function the engine uses).

## Release hygiene
- `app.json` `version` is the single source: `vite.config.ts` injects it as `__APP_VERSION__` (footer of Settings); `package.json` must match (`src/release.test.ts` checks it, plus store manifest rules). Bump both for every release; released versions are immutable.
- **No logging** anywhere (no console, no on-screen debug log): audio, transcripts, translations and keys must never be written out. Errors shown to the user must not echo a key (the browser's WebSocket error quotes the subprotocol, so Deepgram errors are generic). Google's key goes in the `X-Goog-Api-Key` header, never the URL.
- The production build adds a CSP meta tag (`script-src 'self'`, no inline script) — see `vite.config.ts`. It deliberately doesn't set `connect-src`; the Even app enforces the `app.json` network whitelist.
- Keep permissions to what's used (`g2-microphone`, `network`); `PRIVACY.md` must cover each. 1.1.x added no permissions or network origins.
